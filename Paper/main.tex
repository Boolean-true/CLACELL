%\subsection{Context and Significance}
Single-cell RNA sequencing (scRNA-seq) fundamentally transformed genomic research by providing the ability to study gene expressions at the level of individual cells, thereby revealing cellular heterogeneity and enabling the identification of new cell populations. This technology gave the basis for a deeper understanding of complex biological systems and disease mechanisms.

The accurate and reproducible annotation of cell types is a critical prerequisite for deriving meaningful downstream biological insights, such as differential expression analysis, trajectory inference, and gene regulatory network modeling \cite{abdelaal_comparison_2019, luecken_current_2019}. %TODO: Überarbeiten, vor allem nach prerequisite


%\subsection{The Challenge}
Despite the rapid evolution of scRNA-seq technologies, the classification of cell types remains a significant analytical bottleneck. Historically, cell-type annotation has relied heavily on manual marker-based approaches like scumi \cite{ding_systematic_2020}. This traditional method requires the manual specification of marker genes. However, manual annotation is highly subjective, labor-intensive, and therefore scale-limited, making it impractical for modern, atlas-level datasets \cite{abdelaal_comparison_2019}.

To overcome these limitations, numerous classification algorithms were designed that learn from well-annotated reference datasets and transfer these labels to unannotated query datasets. While promising, many of these existing classifiers show substantial drawbacks when deployed on complex tissues like the immune system. Comprehensive benchmarks revealed that these tools frequently suffer from a lack of robustness, yielding poor F1 scores, high variance in classification accuracy, and a high sensitivity to gene dropout \cite{abdelaal_comparison_2019}. %Furthermore, some methods rely on non-deterministic processes, complicating reproducibility. %TODO: Quelle finden um das zu belegen

%An additional layer of complexity arises from the current software ecosystem. A substantial portion of early foundational single-cell preprocessing and normalization tools, including the \texttt{scumi} pipeline \cite{ding_systematic_2020}, were developed in R. In contrast, the modern ecosystem for scalable machine learning and deep learning is predominantly situated within Python, anchored by frameworks such as \texttt{Scanpy} \cite{Wolf2018}, \texttt{scikit-learn}, and \texttt{PyTorch}. This language barrier creates a transition gap that hinders the seamless integration of robust preprocessing routines with advanced, state-of-the-art predictive modeling.

%\subsection{Proposed Solution and Contributions}
To address these challenges, we introduce CLACELL, an open-source Python package engineered specifically for the robust and deterministic classification of immune cells.
CLACELL bridges the gap between specialized bioinformatics preprocessing and high-performance machine learning, providing an end-to-end scalable framework for cell-type annotation. %TODO: Letzten Satz überarbeiten

We compare CLACELL against existing state-of-the-art classifiers, including the machine learning-based CellTypist \cite{dominguez_conde_cross-tissue_2022}, the deep learning model scGPT \cite{cui_scgpt_2024}, and the statistical framework SingleR \cite{aran_reference-based_2019}, using a comprehensive suite of robustness metrics. These metrics evaluate performance under varying conditions of feature loss, gene dropout rates, and cross-dataset batch effects.

The primary contributions of this paper are as follows:

    \item \textbf{Systematic Classifier Benchmark:} We conduct a large-scale evaluation of traditional machine learning models, ensemble methods and autoencoder architectures for immune cell classification.
    \item \textbf{Robustness Demonstration:} We demonstrate CLACELL's robustness against state of the art scRNA-seq classifiers, including feature loss, gene dropout rates, and cross-dataset batch variations. %TODO: Alles ab includinng weglassen?; Evtl hier erst die Vergleichsmodelle erwähnen?

\end{itemize}

\subsection{Comparison of Ensemble and Denoising Approaches}\label{sec:results:ensemble-ae}

We used the Logistic Regression, LinearSVC and Random Forest models to create our custom ensemble and for the Denoising and Conditional Autoencoder. To avoid overcrowded diagrams, we only show the best performing model for each approach. We chose the best model for each approach based on mean Accuracy, Macro F1 score, Random Dropout score and Feature Importance Dropout Score on both in-distribution and out-of-distribution test sets. The best performing model for all three approaches is the LinearSVC.

The custom ensemble with the Random Forest has a slightly better performance than the one with the LinearSVC on the out-of-distribution test set with a small Dropout. At a Feature Importance Dropout of 1\% and 2\% the LinearSVC performs better than the Random Forest. Its performance on the in-distribution test set is significantly higher than the Random Forest. The custom ensemble with the Logistic Regression performs better than the Random Forest on the in-distribution test set, but still slightly worse than the LinearSVC. On the out-of-distribution test set it has a similar performance to the LinearSVC until the Feature Importance Dropout of 0.5\%, where it performs worse than the LinearSVC.

For the Denoising Autoencoder, the LinearSVC provides the best performance in every metric. The Logistic Regression yielded mostly better results than the Random Forest, but worse than the LinearSVC.

The Conditional Autoencoder with the Random Forest performed best in the Accuracy metrics on the in-distribution test set, while the LinearSVC performed best in the Macro F1 score. In the out-of-distribution test set, the LinearSVC performed best in high Feature Importance Dropout rates. The Logistic Regression performed worse than the LinearSVC in every metric. As the Random Forest and LinearSVC have a similar overall performance, we additionally considered the variance of the models. The Random Forest has nearly double the maximum and mean variance of the LinearSVC across all metrics, which is why we chose the LinearSVC as the best performing model for the Conditional Autoencoder.

\subsection{Limitations}\label{sec:discussion:limitations}

Despite the promising results of our study, there are several limitations that should be acknowledged. First, the labels for the training of our classifiers were provided using a marker-based annotation approach. Therefore the quality of the labels is dependent on the quality of the markers. 
Second, we only used a single dataset for training and evaluation, which may limit the generalizability of our findings to other datasets or cell types.
Third, the labels are coarse as the markers from scumi are not very specific. In order to get more specific labels, more fine-grained markers are needed.
Finally, our proposed classifier has a low performance on the Natural Killer cells in the out-of-distribution test set. Therefore it cannot be used for the accurate annotation of this cell type on new datasets.

\subsection{Conclusion \& Future Work}\label{sec:discussion:conclusion}

In this paper, we presented a robust cell type classifier for immune cells based on traditional machine learning methods. Our results demonstrate that our proposed classifier outperforms existing state-of-the-art methods in terms of accuracy and robustness. We also showed that our classifier is able to generalize well to out-of-distribution datasets. It has a low variance, is reproducible and is resource-efficient, requiring only a CPU and approximately 14 GB of RAM for training.

As future work, we plan to classify datasets into more fine-grained cell types. In order to do this, we can either use more specific markers or use a hierarchical classification approach where we add a sub classifier that classifies the cells from coarse classes into finer classes. Additionally, we want to adress the low performance on the Natural Killer cells. This could be done by adding more samples of this cell type to the training dataset or by combining different classifiers in our custom ensemble.

Another potential improvement is to add a rejection class to the classifier. This would allow the classifier to reject samples that it is not confident about, which could increase the overall performance and robustness of our classifier.

\subsection{Marker-Based Annotation}\label{sec:methods:marker-based-annotation}

For the annotation of the in- and out-of-distribution dataset, we used the marker based annotation startegy provided by scumi \cite{ding_systematic_2020} as a R package\footnote{https://bitbucket.org/jerry00/scumi-dev/src/master/R/}. Because of old depenencies we could not use the R package directly. Therefore we re-implemented the marker based annotation strategy in Python. For the labeling of the datasets we used the marker genes provided by scumi.

The annotation strategy clusters the cells based on their gene expression profiles and then assigns cell type labels to each cluster based on the expression of marker genes. To get the optimal clustering, a grid search is performed and the clustering with the best AUC and silhouette score is selected. %TODO: Passt das als Beschreibung zu scumi?

Our Python re-implementation takes a Dataframe with genes $\times$ cells, a marker dictionary and a grid of clustering hyperparameters as input. The hyperparameters consist of the number of nearest neighbors $k$, Leiden resolution $r$, number of principal components $n_{PC}$ and a boolean flag for highly variable gene selection. We provided default values for the clustering hyperparameters, which we used for the labeling of the datasets.
First, rare genes and cells are filtered from the count matrix to reduce noise. Then the gene expression values are normalised to 10.000 counts per cell and log(1+x)-tranformed. A pairwise distance matrix $D \in \mathbb{R}^{n \times n}$ is computed, where $n$ is the number of cells. The distance between each cell is calculated using the squared Euclidean distance between the gene expression of the marker genes. The distance matrix is later used for silhouette evaluation and is not recomputed across parameter combinations.

The parameter grid is the cartesian product of the hyperparameter set. Each candidate is evaluated independently and in parallel. For each candidate, the following steps are performed:
\begin{enumerate}
    \item \textbf{Filtering and Normalization:} As the clustering algorithm receives raw counts, they have to be processed for each candidate. Rare genes and cells are filtered from the count matrix, Mitochondrial genes are identified, and the gene expression values are normalized to 10.000 counts per cell and are log(1+x)-transformed. %TODO: Kann ich die drei Schritte zur Vereinfachung zusammenfassen? Oder sollte ich sie in drei Schritte aufteilen?
    \item \textbf{Feature Selection:} If the highly variable gene selection flag is set to true, highly variable genes are selected. Otherwise, mitochondrial and ribosomal genes are filtered from the dataset.
    \item \textbf{Scaling:} Gene expression values are scaled to have zero mean and unit variance.
    \item \textbf{PCA:} Principal Component Analysisis performed with $n_{PC}$ components.
    \item \textbf{k-NN graph:} A k-nearest neighbor graph is constructed in PCA space with $k$ neighbors.
    \item \textbf{Leiden clustering:} The Leiden algorithm is applied to the k-NN graph with resolution $r$ to identify clusters of cells.
    \item \textbf{t-SNE:} A two-dimensional embedding is computed for potential downstream visualisation.
\end{enumerate}

The resulting cluster vector that assign each cell to a cluster is then evaluated based in a geometric criterion (how well the clusters are separated) and a biological criterion (how confidently each cluster can be assigned to a cell type using the marker definitions). %TODO: So genau erklären?; Oben erwähnen?
The clusters are only evaluated if the number of cluster is within a predefined range $[n_{min}, n_{max}]$.

For the geometric evaluation, the silhouette coefficient for each cell is computed using the distance matrix $D$. The mean silhouette score is then calculated for each cluster.
For the biological evaluation, the ROC-AUC is computed for each cell type and each cluster based on the marker definitions. This yields an AUC matrix $A \in \mathbb{R}^{|c| \times |k|}$, where $|c|$ is the number of cell types and $|k|$ is the number of clusters. Each cluster is assigned to the cell type with the highest AUC. If the assignment is ambiguous ($\text{AUC}<0.9$), undergo an iterative reassignment.
%In each iteration, a detecter AUC and an assignment AUC are computed for each ambiguous cluster. The detecter AUC is the AUC of the cluster against all other clusters that are assigned to the same cell type, while the assignment AUC is the AUC of the cluster when all other clusters that are assigned to the same cell type are removed. If the assignment AUC is higher than the detecter AUC and the class of the cluster is not the only cluster assigned to the cell type, the assignment is updated. %Zu was? Welche Klasse ist jetzt da?
%This procedure iterates until the assignments stabilise or a maximum of five iterations is reached.
In each iteration, ambiguous clusters are evaluated for a potential reassignment to an alternative cell type. Two metrics are computed for every alternative cell type: (1) a detector AUC, which measures how well the ambiguous cluster can be distinguished from all clusters already assigned to this alternative cell type, and (2) an assignment AUC, which evaluates how well the cluster matches the alternative cell type's markers when the clusters that are currently assigned to the alternative cell type are temporarily excluded.
If the alternative cell type yields a higher AUC than the current assignment, and the cluster is not the only representative of its current cell type, its assignment is updated to the new alternative cell type. This procedure iterates until the assignments stabilize or a maximum of five iterations is reached.
Clusters with an AUC below 0.65 are left unlabeled to avoid misclassifications.

The final model is selected by comparing their AUC signals ($\sum_{c} A_{c} - 0.5 |C|$) and the candidate with the stronger signal is chosen. \subsection{Machine Learning Algorithms}\label{sec:methods:machine-learning}

To classify the immune cells based on their gene expression profiles, we evaluated several machine learning models, categorized into linear and tree-based algorithms. For the linear approaches, we implemented Logistic Regression and a Linear Support Vector Classifier (LinearSVC). For tree-based models, we used Random Forest, Extra Trees and LightGBM. The hyperparameter search spaces for each model are detailed in \Cref{tab:ml_hyperparameters}. To ensure compatibility with different loss functions and improve convergence, we used the saga solver with a maximum of 1,000 iterations for Logistic Regression for all iterations. \subsection{Ensemble Learning Strategies}\label{sec:methods:ensemble-learning}

%The top-performing ODER
The best Machine Learning models were combined into a custom feature-subsampling voting ensemble. This ensemble approach was designed to enhance robustness by training multiple instances of the same model on different subsets of features. The feature subsets include the full set of features and three additional subsets where the top features -- determined by a feature importance ranking -- were systematically removed. Specifically, we created subsets by excluding the top 0.75~\%, 1.5~\%, and 2.5~\% of features based on their importance scores.
For the linear models we used the feature importance of the random forest model, while for the tree-based models we used the feature importance of the logistic regression model. 
By using the feature importance of a different machine learning approach, we avoid the bias of the feature importance ranking towards the model that is used for the ensemble. Furthermore the insights from two different approaches are combined to improve the overall performance.

We used a soft voting strategy for the ensemble, where the predicted probabilities of each base model are averaged to make the final prediction. This approach takes the confidence of each base model in its predictions into account, aiming to improve robustness and accuracy.

To save computational resources, we used the optimal hyperparameters from the tuning of the single models for the ensemble.


\subsection{Denoising \& Hybrid Approaches}\label{sec:methods:denoising-hybrid}

The idea behind the Denoising Autoencoder is to learn a robust representation of the input data by reconstructing the original input from a corrupted version. The Encoder learns to map the corrupted input to a latent representation, while the Decoder learns to reconstruct the original input from this latent representation. This approach can help the model to generalize better and be more robust against noise in the input data \cite{lin_scdilt_2025}.
We followed the architecture for Feed-forward autoencoders presented by \textcite{hayashi_conformer-based_2020}: Both Encoder and Decoder of the Denoising Autoencoder consist of two Linear layers with a Batch Normalization, ReLU activation function and a Dropout layer between them.
We used a noise factor of 0.3 to corrupt the input data during training. The first Linear layer of the Encoder reduces the input dimension to 256, while the second Linear layer reduces it to the latent dimension of 128. The first Linear layer of the Decoder increases the latent dimension to 256, while the second Linear layer increases it to the original input dimension.

The Conditional Autoencoder extends the idea of the Denoising Autoencoder by adding additional batch information, such as information about donor origin. This can further improve the robustness and accuracy of the Autoencoder by removing the influence of the donor-specific noise or batch effects. We used the same architecture as for the Denoising Autoencoder and added only the donor ids. They are one-hot encoded and concatenated to the input data for both the Encoder and Decoder \cite{lin_scdilt_2025, hayashi_conformer-based_2020}.
We used a matrix of zeros for the donor ids during inference, as the model only learned the number of donors in the training dataset and therefore cannot handle unseen donors. %TODO: Brauche ich eine Quelle für die Inference phase auf 0 setzen? Meine Quellen belegen das nicht


Both autoencoders were trained for 150 epochs with a batch size of 128 and a learning rate of 0.001 using the AdamW optimizer \cite{loshchilov2018decoupled}. The loss function used was the Mean Squared Error (MSE) loss. We also added an early stopping mechanism to prevent overfitting. The training was stopped if the validation loss did not improve more than 0.0002 for 5 consecutive epochs. %TODO: Quelle MSE loss?

These approaches have to be combined with a classifier, as they only learn a representation of the input data and do not perform classification. We combined the autoencoders with the best-performing machine learning models.
Because of the long training time of the autoencoders on a cpu, we used a RandomizedSearch from scikit-learn \cite{sklearn} with 30 iterations and a 5-fold cross-validation to optimize the hyperparameters of the classifiers. The hyperparameter search space for each machine learning model is displayed in \Cref{tab:ae_ml_hyperparameters}.

Following the baseline evaluation, we introduce three distinct robustness tests to challenge the models:

The Classifier \texttt{CellClassifier} from the CLACELL package implements the custom ensemble with the LinearSVC described in \Cref{sec:methods:ensemble-learning}. It provides four methods:

\begin{itemize}
    \item \texttt{Hyperparameter Optimization (\texttt{grid\_search})} Identifies optimal hyperparameters for the LinearSVC with a random search and offers parallel processing for it. If a training and a test set are provided, it evaluates the hyperparameters with the evaluate method and afterwards calls the train method wit the combined sets and the optimal hyperparameters to train the final model on the whole dataset.
    \item \texttt{Model Training (\texttt{train}):} Trains the LinearSVC with the specified hyperparameters on the given data.
    \item \texttt{Robustness Evaluation (\texttt{evaluate}):} Implements a wrapper around the robustness tests presented in \Cref{sec:methods:robustness-tests} and evaluates the model's performance on the given in distribution and out of distribution test sets. It generates a multi-index evaluation report that can be logged to the console or exported to a file.
    \item \texttt{Inference (\texttt{predict}):} Applies the trained model to new data to predict the immune cell type.
\end{itemize}
