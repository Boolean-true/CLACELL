\begin{abstract}
Single-cell RNA sequencing (scRNA-seq) has transformed genomic research by uncovering cellular heterogeneity; however robust cell type classification remains a significant analytical bottleneck. While manual marker-based annotation is subjective and scale-limited, existing computational classifiers frequently struggle when deployed on complex immune tissues. State-of-the-art models often suffer from high performance variance, sensitivity to gene dropout, and overfitting. 
To address these challenges, we introduce CLACELL, an open-source Python framework engineered for the robust and deterministic classification of immune cells. Rather than relying on a one-size-fits-all approach, CLACELL provides two distinct classifiers for two different priorities: a custom feature-subsampling ensemble model optimized for high prediction stability and low standard deviation, and a Conditional Autoencoder designed for superior out-of-distribution generalization. Both models use a LinearSVC as their base classifier.
We benchmarked both CLACELL models against existing state-of-the-art tools, including CellTypist, scGPT, and SingleR, across different robustness tests on an in-distribution and out-of-distribution dataset. Our results demonstrate that both CLACELL classifiers consistently outperform CellTypist across most metrics and achieve superior generalization on out-of-distribution data compared to SingleR. While scGPT achieved better results on the out-of-distribution test, both CLACELL models performed better on the in-distribution test set. However, scGPT exhibited higher standard deviation, non-deterministic outputs, and required GPU acceleration. Therefore, CLACELL provides two classifiers for different needs with an optimal balance of predictive accuracy, operational robustness, and strict reproducibility.
\end{abstract}

%\subsection{Context and Significance}
Single-cell RNA sequencing (scRNA-seq) fundamentally transformed genomic research by providing the ability to study gene expressions at the level of individual cells, thereby revealing cellular heterogeneity and enabling the identification of new cell populations. This technology gave the basis for a deeper understanding of complex biological systems and disease mechanisms.
The accurate and reproducible annotation of cell types is a critical prerequisite for deriving meaningful downstream biological insights, such as differential expression analysis, trajectory inference, and gene regulatory network modeling \cite{abdelaal_comparison_2019, luecken_current_2019}.


%\subsection{The Challenge}
Despite the rapid evolution of scRNA-seq technologies, the classification of cell types remains a significant analytical bottleneck. Historically, cell-type annotation has relied heavily on manual marker-based approaches like scumi \cite{ding_systematic_2020}. This traditional method requires the manual specification of marker genes. However, manual annotation is highly subjective, labor-intensive, and therefore scale-limited, making it impractical for modern, atlas-level datasets~\cite{abdelaal_comparison_2019}.

To overcome these limitations, numerous classification algorithms were designed that learn from well-annotated reference datasets and transfer these labels to unannotated query datasets. While promising, many of these existing classifiers show substantial drawbacks when deployed on complex tissues like the immune system. Comprehensive benchmarks revealed that these tools frequently suffer from a lack of robustness, yielding poor F1 scores, high variance in classification accuracy, and a high sensitivity to gene dropout \cite{abdelaal_comparison_2019}. %Furthermore, some methods rely on non-deterministic processes, complicating reproducibility. %Quelle finden um das zu belegen

%An additional layer of complexity arises from the current software ecosystem. A substantial portion of early foundational single-cell preprocessing and normalization tools, including the \texttt{scumi} pipeline \cite{ding_systematic_2020}, were developed in R. In contrast, the modern ecosystem for scalable machine learning and deep learning is predominantly situated within Python, anchored by frameworks such as \texttt{Scanpy} \cite{Wolf2018}, \texttt{scikit-learn}, and \texttt{PyTorch}. This language barrier creates a transition gap that hinders the seamless integration of robust preprocessing routines with advanced, state-of-the-art predictive modeling.

%\subsection{Proposed Solution and Contributions}
To address these challenges, we introduce CLACELL, an open-source Python package engineered specifically for the robust and deterministic classification of immune cells.

We compare CLACELL against existing state-of-the-art classifiers, including the machine learning-based CellTypist \cite{dominguez_conde_cross-tissue_2022}, the deep learning model scGPT \cite{cui_scgpt_2024}, and the statistical framework SingleR \cite{aran_reference-based_2019}, using a comprehensive suite of robustness tests.

The primary contributions of this paper are as follows:
\begin{itemize}
    \item \textbf{Development of CLACELL:} We present the architecture and open-source release of the CLACELL package, designed to integrate seamlessly into Python-based single-cell workflows.
    \item \textbf{Systematic Classifier Benchmark:} We conduct a large-scale evaluation of traditional machine learning models, ensemble methods and autoencoder architectures for immune cell classification.
    \item \textbf{Robustness Demonstration:} We demonstrate CLACELL's robustness against state of the art scRNA-seq classifiers, including feature loss, gene dropout rates, and cross-dataset batch variations.
    \item \textbf{Python Reimplementation of \texttt{scumi}:} We provide a native Python reimplementation of the \texttt{scumi} R package's core functionalities \cite{ding_systematic_2020}, eliminating the need for cross-language dependencies for marker based annotation.
\end{itemize}

\subsection{Interpretation of Findings}\label{sec:discussion:interpretation}

In this paper, we evaluated various machine learning algorithms, ensemble strategies, and autoencoder architectures for the robust classification of immune cells. Our findings demonstrate that our two proposed models offer complementary strengths. The custom ensemble yields the most favorable balance of classification accuracy, F1 score, and robustness, while guaranteeing strict reproducibility. Alternatively, the Conditional Autoencoder achieves superior performance on out-of-distribution data while maintaining comparable in-distribution accuracy to the ensemble, at the trade-off of slightly higher prediction instability.


When benchmarked against state-of-the-art reference models, both of our proposed models consistently outperform CellTypist across most evaluated metrics. While SingleR achieves a superior performance on the in-distribution test set, our models surpass it on the out-of-distribution data. This suggests that SingleR has a strong tendency to overfit on the training data. Consequently, it struggles to generalize to unseen data with different underlying distributions or batch effects, which limits its reliability for the zero-shot annotation of new datasets.

In contrast, scGPT demonstrates a strong performance on the out-of-distribution test set and maintains consistency across varying dropout rates. However, this comes at the cost of severe operational drawbacks. scGPT exhibits a remarkably high standard deviation in its performance and suffers from non-deterministic behavior, leading to inconsistent predictions across different runs. To guarantee optimal results, the model requires multiple training iterations followed by manual model selection. But even with this effort, the underlying lack of determinism severely compromises both the reproducibility and the practical robustness of the model. 
Furthermore, scGPT only achieved this high performance after adjustments to the training script as described in \Cref{sec:methods:reference-models}. Without these adjustments, the model's performance was significantly lower. 
Lastly, the model's reliance on GPU acceleration for both training and inference introduces additional resource constraints, further limiting its accessibility for researchers without specialized hardware.

Overall, our models provide the most effective and practical solution for immune cell classification. They successfully bridge the gap between high predictive accuracy and strict reproducibility without the need for additional adjustments. 
Depending on specific research priorities, researchers can choose the model architecture best suited to their experimental needs: the custom ensemble maximizes reliability and strict reproducibility across runs, whereas the Conditional Autoencoder offers a slight advantage in out-of-distribution generalization at the trade-off of slightly higher variability.
However, because both models operate deterministically and avoid severe standard deviation, researchers can fully rely on their outputs without the need for redundant validation runs. Moreover, their high resource efficiency is a distinct advantage: requiring only a standard CPU and approximately 14GB (custom ensemble) or 16GB (Conditional Autoencoder) of RAM for training, they are highly accessible. This allows researchers to perform robust, state-of-the-art cell type annotation without depending on expensive, specialized High-Performance Computing infrastructure.


\subsection{Limitations}\label{sec:discussion:limitations}

Despite the promising results of our study, there are several limitations that should be acknowledged. First, the labels for the training of our classifiers were provided using a marker-based annotation approach. Consequently, the quality of the labels is dependent on the quality of the markers. 
Second, we only used a single dataset for training and evaluation, which may limit the generalizability of our findings to other datasets or cell types.
Third, the labels are coarse as the markers from scumi are not very specific. In order to get more specific labels, more fine-grained markers are needed.
Furthermore, our proposed custom ensemble has a low performance on the Natural Killer cells in the out-of-distribution test set. Therefore it cannot be used for the accurate annotation of this cell type on new datasets.
Finally, a technical limitation regarding the comparability of model efficiency must be noted. Because the initial machine learning models were trained on the \texttt{\$HOME} partition of the HPC cluster, their runtimes were higher than the ones for the custom ensemble, autoencoders, and reference models, which were trained on the \texttt{\$WORK} partition. Therefore, the absolute runtimes across these different models are not perfectly comparable, and the runtime differences should be interpreted with caution.


\subsection{Conclusion and Future Work}\label{sec:discussion:conclusion}

In this paper, we presented two robust cell type classifiers for immune cells based on traditional machine learning methods. Our results demonstrate that our proposed classifiers outperform existing state-of-the-art methods in terms of accuracy and robustness. We also showed that our classifiers are able to generalize well to out-of-distribution datasets. The custom ensemble offers a lower standard deviation, while the Conditional Autoencoders offers a better generalization to out-of-distribution data. Both models are reproducible and resource-efficient, requiring only a CPU and approximately 14~GB (custom ensemble) or 16~GB (Conditional Autoencoder) of RAM for training.

As future work, we plan to classify datasets into more fine-grained cell types. In order to do this, we can either use more specific markers or use a hierarchical classification approach where we add a sub classifier that classifies the cells from coarse classes into finer classes. Additionally, we want to address the low performance of the custom ensemble on the Natural Killer cells. This could be done by adding more samples of this cell type to the training dataset or by combining different classifiers in our custom ensemble.

Another potential improvement is to add a rejection class to the classifiers. This would allow them to reject samples that they are not confident about, which could increase the overall performance and robustness of our classifier.

\subsection{CLACELL Package}\label{sec:package}

The CLACELL package implements our best-performing models, the custom ensemble and the Conditional Autoencoder, both using the LinearSVC as classifier. The package is designed to be user-friendly and easily integrated into existing python workflows for immune cell type classification.
The package can be installed via pip or uv from the Python Package Index~(PyPI).

\paragraph{Annotation}

To train the CLACELL model, a labeled dataset is required. For this purpose, the package provides the \texttt{MarkerAnnotator} class, which serves as an Interface for the re-implementation of the scumi R package presented in \Cref{sec:methods:marker-based-annotation}. The  \texttt{MarkerAnnotator} is initialized with a marker gene dictionary. To annotate an AnnData object~\cite{virshup_anndata_2021}, the user calls the method \texttt{annotate} with the object as an input. It returns the annotated Anndata object with the cell type labels stored in \texttt{adata.obs['scumi-annotation']}, which can then be preprocessed.


\paragraph{Preprocessing}

Before training the CLACELL model, the input dataset needs to be preprocessed. Our package offers a built-in preprocessing pipeline that implements the steps described in \Cref{sec:methods:data-preprocessing}. 
However, this preprocessing pipeline is not mandatory, users can choose to implement their own preprocessing steps if desired. It should include a normalization, log transformation and filtering for highly variable genes, as these steps are crucial for the performance of the CLACELL models.

After preprocessing, the dataset should be split into a training and a test set in order to train and evaluate the model. We highly recommend a split among the batch or donor level to avoid data leakage. The test set size should be between 20\% and 35\% of the total samples.
To use the training and test sets with the CLACELL model, they need to be converted into a dataframe, where the rows represent the samples and the columns represent the genes.
The cell type labels should be stored in a separate series.


\paragraph{Classification}

We provide two classifiers in our package: the \texttt{CellClassifier} and the \texttt{ConditionalCellClassifier}. The first one implements the custom ensemble with the LinearSVC, while the second one implements the Conditional Autoencoder with the LinearSVC. Both classifiers can be used for training and inference on new data. As mentioned in \Cref{sec:discussion:interpretation}, the \texttt{CellClassifier} is recommended when high prediction stability is desired, while the \texttt{ConditionalCellClassifier} is recommended when a superior out-of-distribution generalization is required. For the custom ensemble a Random Forest is additionally trained without hyperparameter tuning to determine the feature importance for the feature subsampling.

Both classifiers provide the same five methods for four different tasks:

\begin{itemize}
    \item \textbf{Hyperparameter Optimization (\texttt{random\_search} and \texttt{bayes\_search}):} Identifies optimal hyperparameters for the LinearSVC with a random search or a bayes search with a custom stopper and offers parallel processing for it. If a training and a test set are provided, it evaluates the hyperparameters with the evaluate method and afterwards calls the train method with the combined sets and the optimal hyperparameters to train the final model on the whole dataset.
    \item \textbf{Model Training (\texttt{train}):} Trains the classifier with the specified hyperparameters for the LinearSVC on the given data.
    \item \textbf{Robustness Evaluation (\texttt{evaluate}):} Implements a wrapper around the robustness tests presented in \Cref{sec:methods:robustness-tests} and evaluates the model's performance on the given in-distribution and out-of-distribution test sets. It generates a multi-index evaluation report that can be logged to the console or exported to a file.
    \item \textbf{Inference (\texttt{predict}):} Applies the trained model to new data to predict the immune cell type. Missing genes in the new data are filled with zeros to ensure compatibility with the model.
\end{itemize}


\subsection{Data Preprocessing}\label{sec:methods:data-preprocessing}

The preprocessing pipeline described in this section was inspired by the scRNA-seq analysis best practices presented by \textcite{luecken_current_2019} and the scanpy tutorial \cite{scanpy_development_team_preprocessing_2026}.
It was applied to both the in-distribution and out-of-distribution datasets. The preprocessing pipeline was designed to ensure that the datasets are comparable and that the models can be trained and evaluated effectively.

Before we started with the preprocessing, we made sure to use the raw counts of the datasets. As we later normalize the data, already normalized data would have been a problem. We also filtered the in distribution dataset for blood data, as it contained more data. The out-of-distribution dataset already only contains blood data.

To prevent the misinterpretation of mitochondrial and ribosomal genes as cell type specific markers, we filtered them out of the datasets. Additionally, hemoglobin genes were removed as part of gene-level quality control to focus on genes relevant for the classification of immune cells \cite{ding_systematic_2020, luecken_current_2019}. %ODER: To prevent models from relying on cell stress and metabolic activity rather than lineage-specific markers, mitochondrial and ribosomal genes were excluded from the dataset. Additionally, hemoglobin genes were filtered out as technical noise from red blood cell lysis to focus solely on biologically relevant immune cell features.
%Doublets were then removed to prevent misclassifications. %ODER
After that we removed doublets to avoid misclassifications \cite{scanpy_development_team_preprocessing_2026}.

To ensure comparable data and soften the mean-variance relationship, we then applied a normalization to a target sum of $1e4$ and log(x+1)-transformation to the datasets \cite{luecken_current_2019}.
%ODER: Then we normalized the data to a target sum of $1e4$ and log(x+1)-transformed it. This ensured that the data is comparable across cells and is normally distributed \cite{luecken_current_2019}.

Finally, we filtered the datasets for highly variable genes to focus on the most informative ones for the cell type classification \cite{scanpy_development_team_preprocessing_2026}. 
To determine the number of highly variable genes to use, we created the elbow plot in \Cref{fig:elbow-plot-gene-count} that shows the variance of the genes in the dataset. It indicates that until around 10,000 genes the biological variance is still greater than 0. Additionally, an empirical evaluation with Random Forest models confirmed that using the top 10,000 highly variable genes yielded the best performance. Therefore, we decided to use this threshold for our analysis.


\subsection{Reference Models}\label{sec:methods:reference-models}

We compare the performance of our proposed classifier to three state of the art models: CellTypist, scGPT and SingleR. All of them use different approaches, ensuring a comprehensive and meaningful benchmark evaluation.


CellTypist \cite{dominguez_conde_cross-tissue_2022} is based on a logistic regression optimized via stochastic gradient descent. It was originally trained on the whole Cross-tissue Immune Cell Atlas dataset with more than just blood cells. We retrained it on the filtered training dataset to make it comparable to our models. For the training we built a wrapper around the CellTypist model so that it uses the Scikit-learn API and can then be tuned the same way as our models. The hyperparameter search space is shown in \Cref{tab:celltypist-hyperparameter-search-space}.

Hyperparameter tuning was performed using Bayesian Optimization via \texttt{BayesSearchCV} from the scikit-optimize library \cite{scikit-optimize_contributors_skoptbayessearchcv_2020} with 30 iterations and a 5-fold cross-validation. Compared to traditional grid or random search strategies, Bayesian optimization offers enhanced efficiency by using past evaluation results to find better parameter choices, thereby finding optimal configurations faster. \cite{NIPS2012_05311655}

To optimize computational resources, a custom early-stopping mechanism was integrated into the optimization. This mechanism terminates the search if the model's performance failed to improve by more than 0.2\% over 5 consecutive iterations. To ensure sufficient initial exploration of the hyperparameter space, this stopper was restricted from triggering until the 15th iteration. Consequently, if no significant improvement was observed between iterations 10 and 15, the search was terminated immediately at the 15th iteration, preventing unnecessary computational overhead.


scGPT \cite{cui_scgpt_2024} is a transformer-based model for single-cell RNA sequencing data analysis and was trained on a large dataset of single-cell RNA sequencing data. 
Due to the computational complexity of training such a large-scale transformer from scratch, we only fine-tuned the pre-trained scGPT model for our comparison. We used the model that was pre-trained on blood data as we only have blood data in our datasets. To finetune scGPT we adjusted the finetuning script provided by the authors on Github\footnote{https://github.com/bowang-lab/scGPT/blob/main/examples/finetune\_integration.py}. Again we built a wrapper to use the Scikit-learn API for our robustness tests.
We didn't perform any hyperparameter tuning for the fine tuning and used the recommended hyperparameters from the authors due to computational constraints.

Initial trainings of the scGPT model revealed that the standard fine-tuning pipeline struggled with extreme class imbalances, frequently failing to learn rare cell types. Furthermore, the default random train-validation split risked completely excluding minor classes from the training subset. To avoid these limitations and stabilize model training, we added two modifications to the pipeline. First, we implemented a stratified cross-validation split to guarantee consistent class proportions across both the training and validation subsets. Second, we applied minority class oversampling, upsampling all cell types with less than 1,000 samples to ensure that each class is sufficiently represented in the training data. These changes lead to a significant improvement in the performance of scGPT and are therefore used for the comparison with our classifier.


SingleR \cite{aran_reference-based_2019} represents a reference-based method for cell type annotation. It computes Spearman rank correlation coefficients between the gene expressions of unlabeled single cells and a reference dataset, assigning the cell type based on the highest aggregated correlation score.
We again built a wrapper around the SingleR model to use the Scikit-learn API for our robustness tests. 
As SingleR scales poorly with the number of cells in the reference dataset, we used a bulked version of the reference dataset for the classification. This means that we computed the mean expression of each gene for each cell type in the reference dataset and used it as the reference for the classification. It reduced the runtime of one run from over 10 hours to just 12 minutes.

\subsection{Marker-Based Annotation}\label{sec:methods:marker-based-annotation}

For the annotation of the in- and out-of-distribution dataset, we used the marker based annotation strategy provided by scumi \cite{ding_systematic_2020} as an R package\footnote{https://bitbucket.org/jerry00/scumi-dev/src/master/R/}. Because of old dependencies we could not use the R package directly. Therefore we re-implemented the marker based annotation strategy in Python. For the labeling of the datasets we used the marker genes provided by scumi.

The annotation strategy clusters the cells based on their gene expression profiles and then assigns cell type labels to each cluster based on the expression of marker genes. To get the optimal clustering, a grid search is performed and the clustering with the best AUC and silhouette score is selected.

Our Python re-implementation takes a Dataframe with genes $\times$ cells, a marker dictionary and a grid of clustering hyperparameters as an input. The hyperparameters consist of the number of nearest neighbors $k$, Leiden resolution $r$, number of principal components $n_{PC}$ and a boolean flag for highly variable gene selection. We provided default values for the clustering hyperparameters, which we used for the labeling of the datasets.
First, rare genes and cells are filtered from the count matrix to reduce noise. Then the gene expression values are normalised to 10,000 counts per cell and log(1+x)-transformed. A pairwise distance matrix $D \in \mathbb{R}^{n \times n}$ is calculated using the squared Euclidean distance between the gene expression of the marker genes, where $n$ is the number of cells. The distance matrix is later used for silhouette evaluation and is not recomputed across parameter combinations.

The parameter grid is the cartesian product of the hyperparameter set. Each candidate is evaluated independently and in parallel. For each candidate, the following steps are performed:
\begin{enumerate}
    \item \textbf{Filtering and Normalization:} As the clustering algorithm receives raw counts, they have to be processed for each candidate. Rare genes and cells are filtered from the count matrix, Mitochondrial genes are identified, and the gene expression values are normalized to 10,000 counts per cell and are log(1+x)-transformed.
    \item \textbf{Feature Selection:} If the highly variable gene selection flag is set to true, highly variable genes are selected. Otherwise, mitochondrial and ribosomal genes are filtered from the dataset.
    \item \textbf{Scaling:} Gene expression values are scaled to have zero mean and unit variance.
    \item \textbf{PCA:} Principal Component Analysis is performed with $n_{PC}$ components.
    \item \textbf{k-NN graph:} A k-nearest neighbor graph is constructed in PCA space with $k$ neighbors.
    \item \textbf{Leiden clustering:} The Leiden algorithm is applied to the k-NN graph with resolution $r$ to identify clusters of cells.
\end{enumerate}

The resulting cluster vector that assign each cell to a cluster is then evaluated based on a geometric criterion (how well the clusters are separated) and a biological criterion (how confidently each cluster can be assigned to a cell type using the marker definitions).
The clusters are only evaluated if the number of clusters is within a predefined range $[n_{min}, n_{max}]$.

For the geometric evaluation, the mean silhouette score over all cells and clusters is computed using the distance matrix $D$.

For the biological evaluation, the ROC-AUC is computed for each cell type and each cluster based on the marker definitions.
Each cluster is assigned to the cell type with the highest AUC. Clusters with an AUC below 0.65 are left unlabeled to avoid misclassifications. If the assignment is ambiguous ($\text{AUC}<0.9$), undergo an iterative reassignment.
In each iteration, a detector AUC and an assignment AUC are computed for each ambiguous cluster for a potential reassignment to an alternative cell type. The detector AUC measures how well the ambiguous cluster can be distinguished from all clusters already assigned to this alternative cell type, while the assignment AUC evaluates the cluster for the alternative cell type when the clusters that are currently assigned to the alternative cell type are temporarily excluded.
If the alternative cell type yields a higher AUC than the current assignment and the cluster is not the only cluster assigned to the current cell type, its assignment is updated to the new alternative cell type. This iterative reassignment continues until the assignments stabilize or a maximum of five iterations is reached.

The candidates with the highest silhouette score and the highest AUC score are re-evaluated on the full filtered matrix. The final model is selected by comparing their AUC scores ($\sum_{c} A_{c} - 0.5 |C|$) and the candidate with the higher score is chosen. The final cell type labels are then computed with the final cluster assignments.


\subsection{Machine Learning Algorithms}\label{sec:methods:machine-learning}

To classify the immune cells based on their gene expression profiles, we evaluated several machine learning models, categorized into linear and tree-based algorithms. For the linear approaches, we implemented Logistic Regression and a Linear Support Vector Classifier (LinearSVC). For tree-based models, we used Random Forest, Extra Trees and LightGBM. With the exception of LightGBM \cite{NIPS2017_6449f44a}, all algorithms were implemented using the scikit-learn library~\cite{sklearn}.

The hyperparameter search spaces for each model are detailed in \Cref{tab:ml_hyperparameters}. To ensure compatibility with different loss functions and improve convergence, we used the saga solver with a maximum of 1,000 iterations for Logistic Regression for all iterations. LightGBM's objective was fixed to multiclass for our evaluation, as it is a multiclass classification problem. Furthermore, the number of parallel jobs was set to 1 as the hyperparameter tuning algorithm already parallelizes the training of the models.

We again used a \texttt{BayesSearchCV} with a custom early-stopping mechanism for hyperparameter tuning, as described in \Cref{sec:methods:reference-models}. The hyperparameter tuning was performed with 30 iterations and a 5-fold cross-validation.


\subsection{Ensemble Learning Strategies}\label{sec:methods:ensemble-learning}

%The top-performing ODER
The best Machine Learning models were combined into a custom feature-subsampling voting ensemble. This ensemble approach was designed to enhance robustness by training multiple instances of the same model on different subsets of features. The feature subsets include the full set of features and three additional subsets where the top features -- determined by a feature importance ranking -- were systematically removed. Specifically, we created subsets by excluding the top 0.75~\%, 1.5~\%, and 2.5~\% of features based on their importance scores.
For the linear models we used the feature importance of the random forest model, while for the tree-based models we used the feature importance of the logistic regression model. 
By using the feature importance of a different machine learning approach, we avoid the bias of the feature importance ranking towards the model that is used for the ensemble. Furthermore the insights from two different approaches are combined to improve the overall performance.

We used a soft voting strategy for the ensemble, where the predicted probabilities of each base model are averaged to make the final prediction. This approach takes the confidence of each base model in its predictions into account, aiming to improve robustness and accuracy.

To save computational resources, we used the optimal hyperparameters from the tuning of the single models for the ensemble.


\subsection{Denoising and Hybrid Approaches}\label{sec:methods:denoising-hybrid}

The idea behind the Denoising Autoencoder is to learn a robust representation of the input data by reconstructing the original input from a corrupted version. The Encoder learns to map the corrupted input to a latent representation, while the Decoder learns to reconstruct the original input from this latent representation. This approach can help the model to generalize better and be more robust against noise in the input data \cite{lin_scdilt_2025}.
We followed the architecture for Feed-forward autoencoders presented by \textcite{hayashi_conformer-based_2020}: Both Encoder and Decoder of the Denoising Autoencoder consist of two Linear layers with a Batch Normalization, ReLU activation function and a Dropout layer between them.
We used a noise factor of 0.3 to corrupt the input data during training. The first Linear layer of the Encoder reduces the input dimension to 256, while the second Linear layer reduces it to the latent dimension of 128. The first Linear layer of the Decoder increases the latent dimension to 256, while the second Linear layer increases it to the original input dimension.

The Conditional Autoencoder extends the idea of the Denoising Autoencoder by adding additional batch information, such as information about donor origin. This can further improve the robustness and accuracy of the Autoencoder by removing the influence of the donor-specific noise or batch effects. We used the same architecture as for the Denoising Autoencoder and added only the donor ids. They are one-hot encoded and concatenated to the input data for both the Encoder and Decoder \cite{lin_scdilt_2025, hayashi_conformer-based_2020}.
We used a matrix of zeros for the donor ids during inference, as the model only learned the number of donors in the training dataset and therefore cannot handle unseen donors.


Both autoencoders were trained for 150 epochs with a batch size of 128 and a learning rate of 0.001 using the AdamW optimizer \cite{loshchilov2018decoupled}. We used the Mean Squared Error (MSE) loss as loss function. We also added an early stopping mechanism to prevent overfitting. The training was stopped if the validation loss did not improve more than 0.0002 for 5 consecutive epochs.

These approaches have to be combined with a classifier, as they only learn a representation of the input data and do not perform classification. We combined the autoencoders with the best-performing machine learning models.
Because of the long training time of the autoencoders on a cpu, we used a RandomizedSearch from scikit-learn \cite{sklearn} with 30 iterations and a 5-fold cross-validation to optimize the hyperparameters of the classifiers. The hyperparameter search space for each machine learning model is displayed in \Cref{tab:ae_ml_hyperparameters}.


\subsection{Robustness Tests}\label{sec:methods:robustness-tests}

The robustness evaluation of the models contains two parts with the same tests: first, models are evaluated on an in-distribution test set, followed by an assessment on an out-of-distribution test set. Comparing model performance on both in-distribution and out-of-distribution test sets allows us to measure their generalization capabilities and robustness against distribution shifts.

The in-distribution test set is a hold-out test set from the same base dataset as the training data. To prevent data leakage, the dataset split was performed on the donors, ensuring that no donor is present in both the training and the test set. The donors for the test set were chosen so that the number of samples in the test set is between 20\% and 35\% of the total samples. Out of all valid splits fulfilling this criterion, we selected the one closest to the mean of 27.5\%. Due to the highly variable number of samples per donor in the base dataset, the final split resulted in a test set size of 33.7\% of the total samples.

The donor-stratified strategy was necessary to avoid data leakage, however, it introduced a significant class imbalance in the final test set. Specifically, Dendritic cells and Megakaryocytes were heavily underrepresented, with only 5 and 7 samples respectively. Given their low representation in the base dataset, a more balanced split was mathematically impossible under the donor-stratification constraint. The results of these classes will be compared to the results on the out-of-distribution test set, which contains a more representative number of samples for these cell types.

As an initial baseline, the performance of the models is evaluated on the full test sets for each distribution. While overall accuracy provides a primary indication of model performance, it is insufficient given the class imbalance of the base dataset. Therefore, we additionally compute a comprehensive classification report from scikit-learn, including precision, recall, F1-score, and support for each individual class, alongside macro and weighted averages. This allows us to assess class-specific model performance.

Following the baseline evaluation, we introduce three distinct robustness tests to challenge the models:

\begin{enumerate}
    \item \textbf{Random Dropout:} We simulate noisy data by randomly selecting 10\% of the input features and setting their values to 0. This test quantifies how the well the model can handle noisy data and how its performance degrades when faced with missing features.
    \item \textbf{Prediction Stability:} To evaluate prediction consistency under stochastic inference, we execute predictions on the same dataset across five independent runs. The number of inconsistent predictions across these iterations is aggregated to measure the stability and standard deviation of the models.
    \item \textbf{Feature Importance Dropout:} The final and most challenging test evaluates model resilience against the loss of highly informative biological signals. We progressively remove the most critical features by setting their values to 0 at four distinct thresholds: 0.1\%, 0.5\%, 1\% and 2\% of the total feature space. The feature importance for the Dropout was determined primarily by the marker genes identified by scumi. Since the number of these marker genes was insufficient to meet the higher percentage thresholds, the remaining top features were supplemented via differential gene expression analysis computed on the training set. This test reveals how heavily each model relies on primary marker genes and how robustly they utilize alternative features when key biological markers are missing. It also assesses how the performance of each model degrades as the proportion of removed important features increases.
\end{enumerate}
